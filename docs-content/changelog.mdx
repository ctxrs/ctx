## 1.6.1

Released: 2026-09-22

### Added

- ctx now discovers and imports conversations from Devin CLI's standard local
  history store. Main and compacted history, linked subagent sessions, and tool
  activity are available to ctx search and replay. Hosted Devin history and
  unlinked background threads are not included.

### Changed

- The website and documentation describe Blame as part of the open-source ctx
  CLI and remove retired commercial-product pages.

### Fixed

- When an index refresh lacks disk space, ctx reports the required and
  available capacity and backs off instead of repeatedly retrying it as an
  internal failure.
- Status and doctor output no longer label a confirmed running daemon unhealthy
  solely because its scheduler heartbeat is old. The heartbeat age remains
  available as a diagnostic in JSON output.
- OpenCode-family imports reject only the affected logical record when an
  individual SQLite value exceeds 16 MiB, while valid sibling history
  continues to import.
- Hosted installs accept setup results with multiline progress output, avoiding
  false setup failures after a successful import.
- Windows hosted installs accept valid multiline transaction receipts, avoiding
  a false installer failure after a successful upgrade.

## 1.5.0

Released: 2026-09-21

### Changed

- Blame is built into the open-source ctx CLI, including source and
  package-manager builds. File, commit, and pull-request attribution retains
  the short and explicit CLI forms and the MCP `blame` tool, with citations and
  text and structured results. Blame no longer requires a Pro companion, trial,
  activation, machine fingerprint, or subscription.
- Blame, its build tools, the installer, and the documentation site now live
  in the public ctx repository.
- Automatic indexing maintains attribution alongside local history. Run
  `ctx setup --wait` or `ctx import --all` to complete it explicitly, including
  in manual mode or when history is already current. Setup's `--no-daemon`
  option continues to suppress refresh.
- `ctx status` and `ctx doctor` report attribution readiness and coverage.
  Blame queries read the existing index without starting a rebuild. A current
  index remains ready when no attribution evidence is available. History
  remains searchable while attribution catches up.
- Existing retained history and citations are preserved. Blame uses the
  unencrypted local `search/attribution/` index; old encrypted Pro data and keys
  are left untouched and unused. Upgrading does not cancel an existing
  subscription.
- For hosted installs from 1.5 onward, uninstalling with no option or
  `--keep-data` preserves history, attribution, and legacy data and keys.
  `--delete-data` is rejected before changes are made; rerun without that
  option. Package-manager and source installs use their original removal
  method. There is no native `ctx uninstall` command.
- Restored the original “search it with ctx” banner and updated documentation
  and bundled agent skills for included Blame, without trial or purchase
  instructions.

  failures using typed causes, without collecting paths or error text.

  directory when `XDG_RUNTIME_DIR` is unset.

## 1.3.2

Released: 2026-09-09

ctx 1.3.2 improves managed upgrades, refresh recovery, Windows installation,
and Semantic packaging while retaining the existing JSON and SDK interfaces.

### Changed

- Stable managed releases now require the complete source-bound semantic model
  and runtime asset set before stable metadata can advance.
- Existing managed installations upgrade through 1.3.2 before moving to later
  stable releases. Ordinary `ctx upgrade` handles the transition, except on
  Windows 0.25.0: rerun the [PowerShell installer](https://ctx.rs/install.ps1)
  because that old executable's self-upgrader cannot complete the update.
  Stop any opted-in legacy ctx daemon before reinstalling.
- The legacy `local_only` JSON and `localOnly` SDK fields remain available but
  are deprecated. Use operation-specific Semantic diagnostics to understand
  execution location; the legacy marker is not a network or privacy guarantee.

### Fixed

- Managed Core and Pro upgrades preserve a truthful applied result and recover
  safely when post-commit finalization or restart work is interrupted.
- Windows managed-pair replacement now handles access-control changes,
  candidate cleanup, and path identity correctly.
- Windows installers preserve command exit codes and diagnostic output in
  PowerShell 5.1 and 7, including successful commands that write to stderr.
- The PowerShell installer recovers managed Windows 0.25.0 installations using
  the authenticated release, without relying on the old broken self-upgrader.
- Windows background processing handles private-directory permissions and
  concurrent readers correctly.
- Refresh restart recovery preserves source-authoritative predecessor rebuilds
  and retained readers without reviving obsolete protocol paths.
- Refresh jobs report completion only after the terminal journal write is
  confirmed; an unconfirmed write remains pending for retry.
- Telemetry reports recovery once queued events finish sending, including
  when delivery resumes after a restart.
- Installer downloads and decompression have bounded work and preserve useful
  failures instead of hanging indefinitely.
- Managed-pair protocol output and automatic-upgrade warnings again follow
  terminal output ownership, including raw and machine-readable modes.

GitHub Release downloads are unmanaged ctx Core-only binaries; the hosted
installer at [ctx.rs/install](https://ctx.rs/install) provides the managed Core
and Pro installation path.

## 1.0.0

2026-08-20

ctx 1.0 is our first major stable release and brings serious performance and
correctness improvements. Cold ingestion of a 4 GB history corpus fell from 44
minutes to 2m22s, about 18x faster, and incremental refresh fell from 4.0s to
0.35s, about 12x faster. The release also adds automatic indexing across more
than 40 local agent-history sources, tracks parent, subagent, fork, and
copied-session lineage, and introduces `ctx blame`, a ctx pro command that connects
files, commits, and pull requests to the agent sessions that produced them.

### Indexing and storage

- Replaced the legacy SQLite/FTS history store with immutable, self-contained
  Tantivy Core generations.
- Complete normalized records now live in Core, so searches and transcript
  reads do not reopen provider databases or files.
- Publications are verified and activated as complete generations. Interrupted
  refreshes retain the last verified generation and safely retry.
- Semantic search now uses optional memory-mapped flat-F32 generations instead
  of `sqlite-vec`.
- Core, semantic, and pro state are bound to committed generations, preventing
  mixed or partially updated results.
- Added route-local incremental refresh, unchanged-source admission, bounded
  generation verification, and writerless no-op refreshes.
- Malformed or conflicting Codex rollouts can be quarantined individually while
  valid sibling histories continue importing.

### Search and structured access

- Added content-aware ranking and explicit `all`, `transcript`, `calls`, and
  `outputs` scopes.

### Breaking changes and upgrade notes

- On first run, ctx 1.0 automatically builds a new immutable Core generation
  from your existing provider histories. It does not convert the legacy index
  in place. The new generation is verified before activation, interrupted
  builds can safely retry, and your original agent history is never modified.
  No manual migration is required.
- `ctx sql` and its persistent relational projection have been removed. Common
  structured-access workflows remain available through indexed
  `ctx list events` filters, JSON/JSONL, `jq`, MCP, and the SDKs. Arbitrary SQL
  is gone, but provider, source, session, lineage, chronology, role, event-type,
  workspace, and file selection have typed indexed equivalents.
- The legacy `--json` shortcut has been removed; use `--format json`.
- Windsurf support was removed because its available source was hook-generated
  output rather than automatically discoverable native history.
- Trae support was removed because its history contract could not be supported
  reliably.
